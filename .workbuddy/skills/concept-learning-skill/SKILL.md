# Concept Learning Material｜概念学习资料生成 Skill

## 概述

本 Skill 用于对**任意新概念**（不限领域、不限语言）生成一份结构化、可信赖、可自测的学习资料。

**核心原则**：不依赖模型记忆闭门造车，必须先检索权威来源、再综合生成。输出像一份微型自学讲义——由「目标与问题驱动（学习目标、核心问题）」到「正文讲解（个人解释、核心机制、应用场景、边界辨析）」再到「效果检验（自测问题）」与「可追溯依据（来源链接）」，形成可自学闭环，便于横向比较与复习。

- **适用范围**：技术、金融、医学、法律、哲学、商业、人文等任意领域；中英文等任意语言名称。
- **单次任务边界**：仅处理**一个概念**；不做长篇课程、不做完整教程。

---

## 适用场景

满足以下任一即可触发本 Skill：

| 场景 | 示例 |
|------|------|
| 陌生概念的系统学习 | 「帮我学习 RAG」「解释一下 黑体辐射」「什么是秃鹰期权策略」 |
| 生成学习资料/笔记 | 「给我生成 XX 的学习资料」「出一份 XX 入门手册」 |
| 概念辨析对比 | 「对比 RAG 与 Fine-tuning」「X 和 Y 的区别」（仍按本结构输出，重点放在"边界辨析"） |
| 输出可保存文档 | 「保存成 HTML / Markdown」「放到 learning-materials/ 目录」 |

**不适用**（直接回答即可，不必启动完整流程）：

- 用户只想要一句话定义的快问快答。
- 用户要求生成完整课程、长篇教材或专著。
- 用户要求做实际代码工程、合同撰写等非"学习资料"产出的任务。

---

## 输入信息

输入全部从用户消息中识别。**「概念名称」是唯一必填项**，其他字段缺失时按默认值处理，**不反向追问用户**。

| 输入项 | 必填 | 缺省处理 |
|--------|------|----------|
| **概念名称**（中/英） | ✅ 是 | 用户消息中无法确定时，必须先追问一次 |
| **用户背景** | 否 | 默认「具备基本常识、对该领域无专业背景的聪明初学者」 |
| **深度偏好** | 否 | 默认「入门到中级」（能向他人解释清楚的深度） |
| **输出语言** | 否 | 与用户提问语言一致 |
| **输出格式** | 否 | 默认对话内 Markdown；要求文件时输出 `.md`/`.html` 并通过 `present_files` 展示 |
| **保存目录**（仅当输出文件时） | 否 | 默认用户当前工作目录下的 `learning-materials/` |

> 关键约束：**概念名称即触发条件**——任意领域、任意语言的"新概念"都可作为本 Skill 的输入。

## 生成步骤

严格按顺序执行下列四步，**不得跳过第 2 步**。

### Step 1｜理解与拆解概念

1. 判断所属领域（技术 / 金融 / 科学 / 法律 / 人文 / …）。
2. 识别可能的中英文别名、缩写、易混淆概念。
3. 消歧义：若同名多义（如 "Java" 指岛屿/语言/咖啡；"Transformer" 指模型/电力/玩具），结合上下文判断；无上下文时取最常见学科义，并在"个人解释"开头一句注明存在其他含义。
4. 列出 2–4 个检索关键词（中英文双语，权威来源多为英文）。

### Step 2｜检索权威来源（强制，不可跳过）

使用 `WebSearch` / `WebFetch` 收集资料，至少覆盖：

- 标准定义与起源（谁提出、何时提出、解决了什么问题）
- 机制/原理说明
- 与 1–3 个相近概念的对比材料
- 至少 2 个真实应用案例
- **至少 1 条**来自概念所属领域的一手来源（官方文档 / 原始论文 / 标准文件）

来源质量按下文「资料来源要求」过滤。

### Step 3｜综合生成资料

按「输出结构」规定的八段式输出，写作硬性约束：

- **目标 ↔ 测评呼应**：「学习目标」中每条能力都必须有对应的「自测问题」；每道自测题的答案在正文内都能找到。
- **核心问题**必须是读完正文才能真正回答的问题，**不得是无需学习即可答出的空问题**。
- **个人解释**必须使用比喻/类比，**禁止直接抄定义**；以「如果只能记住一句话，这个概念是……」收尾。
- **事实性陈述**（年份、人名、数据、机制细节）必须出自 Step 2 的检索结果，**不得凭模型记忆编造**。
- **分歧并列**：来源之间冲突时不要擅自取舍，并列呈现双方说法并标注来源。
- **篇幅控制**：整体 1200–3000 字（中文），宁精勿滥。
- **通用性**：不得夹带特定领域的模板残留（如给非金融概念混入"权利金/行权价"等无关词）。

### Step 4｜自检

按「自检要求」逐项检查，**未通过项必须修正后再交付**。

## 输出结构

**必须且只能**包含以下八节，顺序不可调换。其中 ✅ 五项为本 Skill 的硬性底线，缺一不可。

```markdown
# 【概念名称】学习资料

## 1. 学习目标          ← 引导：读完应会什么
## 2. 核心问题          ← 引导：读完应能答什么
## 3. 个人解释          ← ✅ 通俗、含比喻、以"一句话定义"收尾
## 4. 核心机制          ← ✅ 起源 / 原理 / 关键要素
## 5. 应用场景          ← ✅ 2-4 个真实案例 + 1 个反例
## 6. 边界辨析          ← ✅ 对比表格 + "一句话区分"
## 7. 自测问题          ← 检验：题目 ↔ 目标呼应
## 8. 来源链接          ← ✅ 真实可达、含「标题/URL/贡献说明」
```

各节内容要求：

- **1. 学习目标**：3–4 条；每条以**行为动词**开头（能说出 / 能解释 / 能区分 / 能判断 / 能应用）；每条对应后文某节。
- **2. 核心问题**：3–4 个；指向概念精髓（为什么存在、如何运作、何时使用）；不要常识性问题。
- **3. 个人解释**（✅ 必需）：2–3 段通俗语言；**至少 1 个比喻/类比**；以「如果只能记住一句话，这个概念是……」收尾。
- **4. 核心机制**（✅ 必需）：
  - **起源**：谁在什么背景下提出，解决了什么问题
  - **原理**：分点拆解其内在逻辑或工作流程
  - **关键要素**：3–5 个理解该概念必须掌握的术语
- **5. 应用场景**（✅ 必需）：
  - 2–4 个真实应用案例（每例 2–3 句话，明确领域、用法、成效）
  - **1 个不适用场景**（反例：什么时候用它是错误选择）
- **6. 边界辨析**（✅ 必需）：与 1–3 个最易混淆的相近概念对比，使用表格（维度：定义 / 侧重点 / 典型用法 / **一句话区分**）。
- **7. 自测问题**：4–6 道；题型混合（判断题 / 选择题 / 简答题 至少各 1 道）；题目范围不超纲；每题附简短参考答案（HTML 中可用 `<details>` 折叠）。
- **8. 来源链接**（✅ 必需）：每条含「标题 / URL / 一句话贡献说明」三项；**至少 3 条**独立来源，其中**至少 1 条**一手来源。

---

## 资料来源要求

1. **权威优先**：优先使用官方文档、标准组织、教科书、权威百科（Stanford Encyclopedia 类学术资源、领域内公认机构）。维基百科可用作线索，**不应是唯一来源**。
2. **数量下限**：至少 **3 条**独立来源；其中**至少 1 条**是概念所属领域的一手来源（官方文档、原始论文、标准文件）。
3. **时效性**：技术类概念优先近 2 年资料；若有重大版本/定义演变，须注明当前主流定义与历史差异。
4. **链接真实**：只列**本次实际访问过的 URL**；不可凭记忆编造或猜测；无法验证的来源宁可不列。
5. **分歧标注**：来源之间冲突时不要擅自取舍；正文中并列呈现并标注来源。

## 自检要求

交付前逐项核对，**全部通过方可输出**。

- [ ] **完整性**：八节齐全、顺序正确、无遗漏。
- [ ] **五要素齐备**：✅ 个人解释、✅ 核心机制、✅ 应用场景、✅ 边界辨析、✅ 来源链接 全部覆盖且内容非空。
- [ ] **目标 ↔ 测评呼应**：每条学习目标都有对应自测题；每道自测题的答案在正文中能找到。
- [ ] **通用性**：无任何特定领域的模板残留（如给非金融概念混入"权利金/行权价"，给非技术概念混入"前端/后端"等）。
- [ ] **有据可依**：事实性陈述（数据、年份、人名、机制）均能在「来源链接」中找到支撑；无凭空编造。
- [ ] **通俗性**：个人解释含比喻，初学者不依赖领域前置知识即可读懂。
- [ ] **辨析有效**：「一句话区分」能让读者快速分辨相近概念。
- [ ] **链接可达**：所有 URL 都来自本次真实检索结果，格式完整（标题 / URL / 贡献说明）。
- [ ] **篇幅合规**：整体 1200–3000 字（中文），无冗余。

## 输出格式约定

- **默认**：对话内直接以 Markdown 输出八段式资料。
- **用户要求文件时**：保存为 `概念名-学习资料.md`（或 HTML）到指定目录，通过 `present_files` 展示。
- **HTML 增强**：自测问题参考答案用 `<details>` 折叠，便于先自测再核对。
- **可视化请求**：用户要求图表辅助时，可在「核心机制」部分配合 Visualizer 添加示意图。

## 关键原则速览

| 原则 | 含义 |
|------|------|
| **输入即概念** | 唯一必填输入是概念名称；任意领域、任意语言 |
| **检索先行** | 严禁先写后补；先权威检索、再综合生成 |
| **结构固定** | 八段式是输出契约，不可增删改序 |
| **可追溯** | 所有事实回到来源；链接真实可达 |
| **可自测** | 「学习目标」与「自测问题」一一呼应，形成自学闭环 |
| **通用** | 不夹带领域模板残留；不预判用户专业背景 |
