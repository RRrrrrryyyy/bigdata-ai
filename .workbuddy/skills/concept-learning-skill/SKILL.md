# Concept Learning Material（概念学习资料生成）

## 概述

本技能用于对**任意新概念**生成一份结构化、可信赖、便于快速入门的学习资料。核心原则：不依赖模型记忆闭门造车，必须先检索权威来源，再综合生成；输出结构固定，便于横向比较与复习。

## 适用场景

- 用户提出一个陌生概念并希望系统学习（"帮我学习 RAG"、"什么是期权秃鹰策略"）
- 用户要求为某个概念生成笔记、学习卡片或入门材料
- 用户要求辨析两个相似概念（此时仍按本结构输出，重点放在"边界辨析"）
- 概念可以是任何领域的名词：技术、金融、医学、法律、哲学、商业等，中英文均可

不适用：用户只想要一句话定义的快问快答（直接回答即可，无需启动完整流程）；用户要求生成完整课程或长篇教程（超出单概念范围）。

## 输入信息

触发本技能后，从用户消息中识别以下输入。**概念名称为唯一必需项**，其余缺失时按默认值处理，不反向追问用户：

| 输入项 | 必填 | 缺省处理 |
|--------|------|----------|
| 概念名称（中/英文） | 是 | 无缺省值；若用户消息中无法确定概念，则必须先询问 |
| 用户背景 | 否 | 默认假设为"有基本常识、无该领域专业背景的聪明的初学者" |
| 深度偏好 | 否 | 默认"入门到中级"（能向同事解释清楚的水平） |
| 输出语言 | 否 | 与用户提问语言一致 |
| 输出格式 | 否 | 默认在对话中直接输出 Markdown；若用户要求文档，则生成 .md 文件并通过 present_files 展示 |

## 生成步骤

按顺序执行以下四步，不得跳过第 1 步：

### 第 1 步：理解与拆解概念

1. 判断概念所属领域（技术/金融/科学/法律/人文等），识别可能的中英文别名、缩写、易混淆概念。
2. 若概念名称有歧义（如 "Java" 可能指岛、语言或咖啡），根据用户上下文判断；无上下文时选择最常见的学科含义，并在资料开头注明存在其他含义。
3. 列出 2-4 个待检索的关键词（含英文关键词，权威来源多为英文）。

### 第 2 步：检索权威来源

必须先检索再写作。使用 WebSearch / WebFetch 收集资料，来源要求见下文"资料来源要求"。检索时至少覆盖：

- 概念的标准定义与起源（谁提出、何时提出）
- 概念的原理或机制说明
- 概念与相近概念的对比材料
- 至少 2 个真实应用案例

### 第 3 步：综合生成资料

将检索结果综合为下文"输出结构"规定的五段式资料。写作要求：

- "个人解释"必须使用比喻或类比，禁止直接照抄定义
- 事实性内容（年份、人名、数据、机制细节）必须来自检索结果，不得凭记忆编造
- 检索到的信息相互矛盾时，注明分歧并列出双方来源
- 篇幅控制：整体 800-2000 字（中文），宁精勿滥

### 第 4 步：自检

对照下文"自检要求"逐项检查，未通过项必须修正后再交付。

## 输出结构

输出必须包含且仅包含以下五个部分，按此顺序排列：

```markdown
# 【概念名称】学习资料

## 1. 个人解释
用 2-3 段通俗语言，面向缺省用户背景解释这个概念。
必须包含至少一个比喻或生活化类比。
以"如果只能记住一句话，这个概念是……"收尾。

## 2. 核心机制
说明这个概念"为什么成立、如何运作"：
- 起源：谁在什么背景下提出，解决了什么问题
- 原理：拆解其内在逻辑或工作流程，分点陈述
- 关键要素：列出 3-5 个理解该概念必须掌握的术语

## 3. 应用场景
- 2-4 个真实世界中的应用案例（来自检索结果，注明出处领域）
- 每个案例 2-3 句话：谁在什么情况下用它、达成了什么效果
- 附 1 个"不适用场景"（什么时候用它是错误的选择）

## 4. 边界辨析
- 与 1-3 个最易混淆的相近概念对比
- 使用对比表格：维度（定义/侧重点/典型用法/一句话区分）
- 用"一句话区分"行让读者能快速分辨

## 5. 来源链接
列出本次生成实际参考的来源，每条包含：标题、URL、一句话说明该来源贡献了什么。
至少 3 条，且满足下文"资料来源要求"。
```

## 资料来源要求

1. **权威优先**：优先使用官方文档、标准组织、教科书、权威百科（如官方文档、Stanford/Stanford Encyclopedia 类学术资源、领域内公认机构）。维基百科可用作线索，但不应是唯一来源。
2. **数量下限**：至少 3 条独立来源；至少 1 条来自概念所属领域的一手来源（官方文档、原始论文、标准文件）。
3. **时效性**：技术类概念优先检索近 2 年的资料；概念本身有重大版本/定义演变时，须注明当前主流定义与历史差异。
4. **链接真实**：只列出实际检索/访问过的 URL；不得凭记忆编造或猜测链接。无法验证的来源宁可不列。
5. **标注分歧**：来源之间定义冲突时，不得擅自取舍，须在正文中并列呈现。

## 自检要求

交付前逐项自检，全部通过方可输出：

- [ ] **完整性**：五个部分全部存在且顺序正确，无遗漏
- [ ] **通用性**：未夹带任何特定领域的模板残留（如给金融概念套了技术模板的残留句式）
- [ ] **有据可依**：所有事实性陈述（数据、年份、人名、机制）均可在"来源链接"中找到支撑；无凭空编造内容
- [ ] **通俗性**：个人解释包含比喻，且不要求读者具备该领域专业背景即可读懂
- [ ] **辨析有效**：边界辨析的"一句话区分"确实能让读者区分开相近概念
- [ ] **链接可达**：所列 URL 均来自本次真实检索结果，格式完整（含标题、URL、贡献说明）
- [ ] **篇幅合规**：整体在 800-2000 字（中文）之间，无冗余废话

## 输出格式约定

- 默认在对话中直接以 Markdown 输出五段式资料
- 用户明确要求文件时，保存为 `概念名-学习资料.md` 到当前工作目录，并使用 present_files 展示
- 用户要求图表辅助理解时，可配合 Visualizer 在"核心机制"部分增加示意图
