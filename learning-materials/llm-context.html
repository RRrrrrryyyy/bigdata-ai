大模型的上下文（Context）学习资料

领域：人工智能 / 大模型应用  |  深度：入门到中级

1. 学习目标

  • 能说出"上下文"与"上下文窗口"的含义，并用比喻向外行解释（对应第 3 节）。
  • 能解释上下文由哪些信息构成、为什么它是模型唯一的"短期记忆"（对应第 4 节）。
  • 能区分上下文、提示词与上下文工程三者的关系（对应第 6 节）。
  • 能判断"塞更多资料进上下文"在什么时候反而有害，并说出替代做法（对应第 5 节）。

2. 核心问题

  1. 模型没有长期记忆，却能在长对话里"记得"你说过的话——它是怎么做到的？代价是什么？
  2. 为什么同一个模型、同一句提示词，换一批"喂进去的资料"后输出质量会天差地别？
  3. 上下文窗口已经到 128K 甚至更大，为什么工程师还在研究"压缩"和"取舍"而不是全塞进去？

3. 个人解释

想象你请了一位临时工来家里干活。这位临时工有个怪癖：他没有任何长期记忆，只能看到眼前工作台（白板）上摆着的东西。你把扫把、拖把、"哪些东西不能扔"的清单、上次的工作笔记都摆上白板，他立刻干得又快又好；你什么都没摆，只甩一句"把客厅收拾了"，他就只能瞎干。大模型就是这位临时工，而上下文（Context）就是那块白板上的全部内容——系统指令、聊天历史、检索来的资料、工具返回的结果、你当前的问题，全都摆在这块板上。

这块白板有两个要害：一是容量有限（叫"上下文窗口"，以 token 计），写满了就得擦掉旧内容；二是板上的东西直接决定他的表现——同一个模型，板上放着退款政策原文，它就能答得精准；板上空空如也，它就只能靠训练时的印象"猜"，于是开始胡说（幻觉）。所以业内才说：模型每次回答时，它的"整个世界"就是当前的上下文窗口——不在窗口里的东西，对它而言不存在。

如果只能记住一句话：上下文就是模型每次回答时唯一能"看见"的全部信息，它是模型的短期记忆，决定了模型答得好不好。

4. 核心机制

起源

"上下文"伴随 Transformer 架构自回归生成而天然存在——模型只能基于当前输入序列预测下一个 token。随着 LLM 应用走向复杂，2024–2025 年业界（IBM、Anthropic 生态等）把"系统设计喂给模型的全部信息"从提示词工程中独立出来，形成"上下文工程（Context Engineering）"这一学科，被视为提示词工程的自然演进。

原理：上下文的构成与约束

  • 构成：系统提示（身份与规则）、用户当前查询、检索到的外部文档（RAG）、对话历史、工具返回结果、记忆条目——它们共同拼成模型一次推理看到的全部输入。
  • 有限预算：上下文窗口以 token 计（如 128K、200K），输入输出都算在内；窗口即"短期记忆"，模型没有真正的长期记忆。
  • 质量衰减：窗口越大不等于越好——资料过多会稀释注意力，出现"中间遗忘（lost in the middle）"、上下文中毒、上下文分心等失败模式。
  • 管理手段：检索筛选（只放最相关的）、压缩与摘要、排序（重要信息靠前）、工具与记忆集成——这些正是上下文工程的核心步骤。

关键要素（必掌握术语）

  • Context Window（上下文窗口）：模型单次推理能"一眼看全"的最大 token 量。
  • Token：模型处理文本的最小单位（可理解为被切碎的词块），是窗口的计量单位。
  • System Prompt（系统提示）：定义模型身份与规则的指令，位于上下文的最高优先级位置。
  • RAG（检索增强生成）：从外部库检索资料放进上下文的技术，是上下文的重要来源。
  • Context Engineering（上下文工程）：系统设计、筛选、组织上下文以最大化输出质量的工程实践。

5. 应用场景

企业知识库问答（RAG 系统）：把退款政策、产品文档检索后放入上下文，模型从"靠印象猜"变成"照原文答"，幻觉显著减少——IBM 指出此类系统的性能往往更多取决于上下文质量而非模型大小。
智能体（Agent）的记忆管理：Agent 每步调工具都会产生新上下文，工程上必须决定哪些保留、哪些摘要压缩、哪些存入外部记忆，否则几步之后窗口就被工具输出挤爆。
长对话与长文档处理：多轮聊天会持续吃掉窗口额度，通过滚动摘要、选择性保留历史，让模型在有限窗口里始终"记得"关键信息。
不适用场景：认为"窗口够大，把所有资料一股脑塞进去就行"。研究表明塞满噪声的长上下文会让模型抓不住重点（中间遗忘），还会推高成本与延迟——正确做法是精选与压缩，而非堆料。

7. 自测问题

（判断）1. 上下文窗口越大，模型回答质量一定越好。

参考答案

错。过多信息会稀释注意力，出现"中间遗忘"等失败模式；精选、压缩后的短上下文常比塞满噪声的长上下文效果更好、成本更低。

（选择）2. 下列哪一项通常不属于一次推理时的上下文？A. 系统提示 B. 检索到的文档 C. 模型的训练权重 D. 对话历史

参考答案

C。训练权重是模型的"长期能力"，不在推理时的上下文里；上下文只包含系统提示、查询、历史、检索资料、工具结果等输入信息。

（选择）3. "提示词工程是'问什么'，上下文工程是'在什么信息背景下问'"——这个对比说明上下文工程是提示词工程的：A. 替代品 B. 子集 C. 扩展与演进 D. 无关领域

参考答案

C。IBM 等来源把上下文工程视为提示词工程的自然演进：提示词工程只管指令措辞，上下文工程管理整个信息载荷。

（简答）4. 用"临时工与白板"的比喻向外行解释上下文和上下文窗口。

参考答案

模型像没有长期记忆的临时工，只能看到白板（上下文窗口）上摆的东西；板上摆好工具和说明他就干得好，板容量有限，写满就得擦掉旧内容。

（简答）5. 列举上下文通常包含的至少四类信息。

参考答案

系统提示、用户当前查询、对话历史、检索到的外部文档、工具返回结果、记忆条目（任答四类即可）。
